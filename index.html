01

Full-Stack · Solo Build · AI-First

A complete online store I built on my own, AI-first with Claude Code: a Next.js storefront, a React admin panel and an Express API over 38 data models — catalog, cart, coupons, checkout, order tracking and a drag-and-drop homepage builder.

Next.js 14React 18ExpressPrismaMySQLRedisDockerClaude Code
Problem

A small retailer needs what the big platforms have — a fast storefront, a real admin panel, order alerts, ad tracking — without a team to build it. The hard parts are the ones customers never see: pricing that cannot be tampered with, stock that cannot oversell, sessions that cannot be stolen.

Approach

I wrote the spec, then built storefront, admin and API as one monorepo with shared validation schemas, working with Claude Code feature by feature and reviewing every change. The server owns pricing and stock; orders trigger email and WhatsApp alerts; conversion tracking and a product feed plug into ad platforms; CI checks dependencies on every push.

Impact
  • Storefront, admin panel and API shipped by one engineer
  • Two simultaneous adds can never oversell the last item
  • Refresh token moved to an HttpOnly cookie after a security pass
  • Products import and export between stores, including Shopify format

03

AI Operations · Feature Owner

A console for monitoring and governing fleets of AI agents — reliability, latency, cost, drift and audit views drawn from agent telemetry, plus a chat that answers questions about what the agents have been doing.

React 19TanStack RouterTanStack QueryTailwind v4Custom SVG chartsVitest
Problem

Approach

04

Identity & Billing · SaaS Platform

One portal for a family of SaaS apps: users sign in once and reach every app they have access to, owners manage members and per-app roles, and admins manage the app catalog and pricing plans synced to Stripe.

React 19TanStack RouterTanStack QueryStripe CheckoutDelegated loginVitest
Problem

Every app had its own sign-in, members and billing. Invites broke on edge cases — wrong account, page refresh, expired session — and paid plans could not be bought until someone set them up in Stripe by hand.

Approach

I delivered the console redesign, owner and admin roles with ownership transfer, a single accept-invite page with a “wrong account” screen, route guards that keep the return path, and the billing screens — plan catalog, checkout, cancellation and plan switching.

Impact
  • Registering an app creates its Stripe product automatically
  • An abandoned invite no longer redirects the next person to sign in
  • Prices lock once synced, so billing cannot drift
  • Signed-out visitors can no longer reach portal pages
05

AI Application Platform · Front Ends

Production front ends for apps whose backends run on an application operating system (AOS) platform — typed entities, serverless functions and AI agents — including an at-home concierge service and a production-management system for a flooring business.

ReactTypeScriptServer-Sent EventsAI agentsServerless functionsStripe
Problem

Agent-driven screens depend on long-lived streams. When the onboarding chat dropped mid-conversation, reconnecting replayed earlier messages and repeated their side effects — a second passcode prompt, a repeated sign-up step.

Approach

I made the agent stream resilient: reconnect with backoff and jitter, resume from the last event id, keep the stream alive in background tabs, treat sign-in failures as final, and de-duplicate replayed turns by id. Elsewhere I extended an AI extraction upload to accept CSV exports as well as PDFs.

Impact
  • Chats survive dropped connections without repeating steps
  • Sales orders import from CSV or PDF through one AI pipeline
  • Customer lists read from the authoritative tenant table
  • Same patterns reused across several apps on the platform

AI Workspace · Frontend Lead

Claude OpenAI Gemini +6–7 more

Frontend approach

Problem

The hard part wasn't generating the code — it was making the UI feel instant while orchestrating multi-step LLM generation, schema synthesis and cloud deploy under the hood. Founders without engineering teams were burning quarters of runway just to validate a hypothesis.

Frontend approach

I led the frontend architecture: a streaming-first shell where every generation step renders progressively, with optimistic step previews and a full-screen diff viewer that handles five-thousand-line outputs without dropping a frame. State coordinated through a deliberate split — NgRx for the run lifecycle, Signals for everything ephemeral. I also built the in-app API explorer with live execution, the agent code-generation screen and auto-save for long requirement forms.

The point isn't the framework. The point is that a non-technical founder ships a working prototype before lunch.

AI Search · Climate Tech

A semantic document search and retrieval experience for a climate-tech nonprofit — turning a sprawling corpus of policy, program and incentive docs into instant answers grounded in their source passages.

Semantic SearchVector EmbeddingsRAG PipelineRetrieval API
Problem

The client's research and program documents had grown into a large, unstructured corpus. Stakeholders spent hours digging through PDFs for clauses, rebates and program details — and keyword search fell short, since the same idea gets phrased a dozen ways across revisions.

Frontend approach

I helped deliver the search experience behind their existing product UI — ingestion and chunking, vector embeddings, a semantically indexed retrieval layer, and a clean API returning ranked passages with grounded citations, tuned for the shape of policy and incentive content.

Impact
  • Hours of manual hunting compressed into seconds of search

  • Drop-in API integrated cleanly with the existing product
